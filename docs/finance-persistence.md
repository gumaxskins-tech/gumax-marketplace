# Finance persistence

Completed: ledger, hold, order, payment and refund idempotency extraction, plus payment event/webhook deduplication, each behind an explicit in-memory adapter for tests. P0-A1.1a is complete: all six idempotency/deduplication mechanisms are decoupled from FinanceService. LedgerRepository, WalletRepository, HoldRepository, OrderRepository, PaymentRepository, RefundRepository and InventoryReservationRepository are also extracted and currently use in-memory adapters; they are not PostgreSQL persistence. Wallet balance remains derived from the ledger. P0-A1.1b is complete only in the sense that main finance and inventory-reservation storage is behind repository ports.

Pending: an async repository boundary; persistent idempotency adapters; Prisma adapters; PostgreSQL transactions; row-level locking or conditional reservation; atomic order/reservation, payment/order/event-dedup/audit and hold/ledger-capture flows; and persistent wallet/ledger/payment/refund state. RefundRepository is in-memory only; refunds still have no ledger effect, and refund/payment/audit are not a PostgreSQL transaction. The item-only reservation model has no ownership-based foreign-release validation or FinanceService release flow. In-memory reservation exclusivity applies only to a shared adapter in one process. P0-A1 is not complete.
